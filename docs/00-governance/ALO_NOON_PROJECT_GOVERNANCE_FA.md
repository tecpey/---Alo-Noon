# حاکمیت دائمی پروژه الو نون

- **وضعیت:** Authority
- **مالک تصمیم:** بنیان‌گذار، محصول، معماری، امنیت و عملیات
- **دامنه:** تمام مستندات، کد، داده، زیرساخت، طراحی، عملیات و خروجی‌های AI
- **قاعده تغییر:** هر تغییر ماهوی نیازمند ADR یا Decision Log و PR قابل ممیزی
  است.

## اصل راهبردی

الو نون یک اپ ساده سفارش نان نیست؛ یک پلتفرم عملیاتی API-first، چندشهری و
چندمستاجری است که باید از پایلوت کنترل‌شده بابل به محصولی مقیاس‌پذیر، امن و قابل
دفاع تبدیل شود. استاندارد کیفیت و سخت‌گیری مدیریتی پروژه تک‌پی در این پروژه نیز
اعمال می‌شود، اما معماری دامنه مالی تک‌پی کورکورانه کپی نمی‌شود.

## قواعد الزام‌آور اجرا

1. کیفیت، امنیت، صحت داده و معماری بر سرعت ظاهری مقدم‌اند.
2. هر فاز با ممیزی وضعیت واقعی، ریسک‌ها، وابستگی‌ها، معیار پذیرش و Roll-forward
   آغاز می‌شود.
3. تغییرات فقط روی Branch و PR مستقل انجام می‌شوند و Merge منوط به Migration،
   Format، Lint، Typecheck، Test و Build سبز است.
4. PostgreSQL و Backend منبع حقیقت‌اند. داده حیاتی کاربر، سفارش، CRM، عملیات و
   AI نباید در localStorage یا حافظه دستگاه منبع اصلی باشد.
5. قابلیت پیاده‌سازی‌شده باید از Target Architecture صریحاً تفکیک شود.
6. تصمیم مهم محصول، معماری، امنیت یا عملیات نباید فقط در گفتگو باقی بماند.

## معماری و داده

- Modular Monolith فعلی حفظ می‌شود تا شواهد عملی استخراج سرویس را توجیه کند.
- قراردادها نسخه‌دار، API-first و مناسب وب، اپ مشتری، اپ پیک، پنل نانوایی،
  اپراتور تلفنی و داشبورد مدیریت هستند.
- Tenant مرز اپراتور مستقل، فرنچایز یا White-label است؛ شهر، نانوایی، شعبه، شریک
  پیک، خانواده یا مشتری Tenant نیستند.
- هویت می‌تواند سراسری باشد، اما عضویت، نقش، مجوز، داده، Cache، Queue، Event،
  Log، Trace، Analytics، File و AI Memory باید Tenant-aware باشند.
- دسترسی بین مستاجری Deny-by-default است و با تست منفی، Audit و در مراحل بعد
  PostgreSQL RLS اثبات می‌شود.
- هیچ شناسه Tenant ارسال‌شده توسط Client به‌تنهایی مجوز ایجاد نمی‌کند.
- Migration داده باید Fail-closed، قابل تکرار در CI و فاقد حدس مالکیت باشد.

## محصول، برند و تازگی

- وعده اصلی «نان تازه» است، نه الزاماً «نان داغ».
- فقط نان‌های Signature اختصاصی با جریان تولید/تحویل کنترل‌شده به‌عنوان تازه
  عرضه می‌شوند.
- نان‌های سنتی معمولی، فانتزی و رژیمی در مدل بسته‌بندی‌شده عرضه می‌شوند.
- محصولات ویژه، پیش‌سفارش، ظرفیت تولید، کنترل کیفیت، بسته‌بندی، Batch، Dispatch،
  ETA و رهگیری بخشی از دامنه اصلی‌اند.
- شعار «نان داغ، زندگی گرم» تا تصمیم رسمی برند وارد Production نمی‌شود.
- فایل‌های تصویری فعلی لوگو Reference هستند؛ Production به Master وکتور، نسخه
  تک‌رنگ/معکوس، آیکون و قواعد فضای امن نیاز دارد.
- UI/UX باید فارسی‌اول، دسترس‌پذیر، سریع، برندمحور و فاقد ظاهر کلیشه‌ای فروشگاهی
  یا AI-generated باشد.

## CRM و عملیات

- CRM از روز اول حافظه مرکزی مشتری، خانواده، آدرس، ترجیحات، سفارش، تماس، شکایت،
  رضایت، کمپین، نانوایی، شعبه، پیک و شریک لجستیکی است.
- سفارش تلفنی در همان OMS ثبت می‌شود و جریان دستی یا دیتابیس جدا ندارد.
- پایلوت بابل فقط با Gateهای کیفیت، SLA، اقتصاد هر سفارش، رضایت، تسویه و تکرار
  خرید گسترش می‌یابد.
- ناوگان برقی و اشتغال رانندگان زن یک برنامه مرحله‌ای و قابل‌اندازه‌گیری است؛
  ادعای کاهش هزینه یا اثر اجتماعی پیش از داده واقعی قطعی تلقی نمی‌شود.

## امنیت، مالی و حریم خصوصی

- Least privilege، RBAC، Audit Log، Idempotency، Encryption، حداقل‌سازی PII،
  Retention و Secret isolation الزامی‌اند.
- تغییرات مالی به دفترکل غیرقابل‌تحریف، Idempotency و تایید انسانی نیاز دارند.
- هیچ قابلیت Production-ready اعلام نمی‌شود مگر تهدیدها، شکست‌ها، بازیابی،
  مانیتورینگ و Runbook آن اثبات شده باشد.

## AI Operations و AI C-Level

- نقش‌های CEO، CTO، CPO، COO، CISO، CFO، CX/CRM و Data/AI مشاورند.
- AI فقط به Evidence تاییدشده، حداقل دسترسی، Provenance، Redaction، Retention،
  Versioned Instructions و Evaluation دسترسی دارد.
- AI می‌تواند Log/Trace/Metric را تحلیل، Incident را اولویت‌بندی، Patch پیشنهاد
  و در Sandbox تست کند و Draft PR بسازد.
- AI بدون Policy و تایید انسانی حق Deploy، تغییر Production، دسترسی به Secret،
  اقدام مالی، تغییر Permission یا عبور بین Tenantها را ندارد.
- مسیر اصلاح: Evidence → Redaction → Analysis → Sandbox → Test → Draft PR →
  Human Review.
- گفتگوهای خام مدل منبع حقیقت یا حافظه تاییدشده پروژه نیستند.

## تعریف پایان هر فاز

یک فاز فقط زمانی پایان‌یافته است که کد و اسناد همگام، CI سبز، Migration آزموده،
اثر امنیت/حریم خصوصی مشخص، عملیات و Roll-forward مستند، و ادعاهای محصول با
قابلیت واقعی منطبق باشند.
